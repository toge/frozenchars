# wildcard.hpp 最適化設計

## 概要

`include/frozenchars/wildcard.hpp` の実行時オーバーヘッドを削減する。公開 API と既存挙動は維持しつつ、`wildcard_match`、`wildcard_find`、`wildcard_find_all` の高速化を行う。

## 目的

- パターンを毎回再解釈するコストを削減する
- 単純な glob パターンをより短い実行経路で処理する
- `find` 系 API の無駄な再試行を減らす
- 既存テストを壊さず、既存ベンチで改善を確認できる状態にする

## 対象範囲

今回の変更対象は以下に限定する。

- `wildcard_match`
- `wildcard_find`
- `wildcard_find_all`
- これらを支える `detail` 名前空間内の補助実装
- 必要最小限のテスト追加

今回の変更では以下は対象外とする。

- 公開 API の追加・削除・変更
- `frozen_regex` の実装変更
- ベンチマーク基盤そのものの作り替え

## 設計方針

### 1. パターンのコンパイル時計画化

`PAT` は NTTP なので、パターンから得られる構造情報を consteval で前計算する。

前計算対象:

- `[` に対応する `]` の位置
- `(` に対応する `)` の位置
- alternatives の branch 境界
- 文字集合ごとの文字判定テーブル
- 単純 glob (`*`, `?`, リテラルのみ) かどうかの判定
- `find` 系で再利用できる固定プレフィックス情報

これにより、実行時 matcher はパターン文字列そのものを逐次解析するのではなく、解析済みメタデータを参照して分岐する。

### 2. 実行経路の優先順位

`wildcard_match` の実行経路は以下の優先順位とする。

1. 既存の `frozen_regex` 委譲が可能ならそのまま委譲
2. 単純 glob パターンなら iterative greedy matcher に送る
3. それ以外は前計算メタデータ付き一般 matcher を使う

この順序により、既存の非常に速い委譲パスは維持しつつ、一般 matcher に入る前のコストを削減する。

### 3. 単純 glob 専用 greedy matcher

`[]`、`()`、escape を含まないパターンに対しては、`*` と `?` のみを扱う線形 greedy matcher を追加する。

この matcher は以下の状態だけを持つ。

- text 側の現在位置
- pattern 側の現在位置
- 最後に見た `*` の位置
- `*` が消費した text の再開位置

この経路では再帰を使わず、典型的な `a*b*c` 系パターンを低コストで処理する。

### 4. 一般 matcher の高速化

一般 matcher では以下を適用する。

- `[` / `(` の閉じ位置探索を実行時に行わず前計算値を使う
- 文字集合は都度 `read_one` せず、前計算した 256 エントリの lookup table で判定する
- alternatives は branch 境界を前計算し、毎回 `|` を走査しない
- 既存の `*` 後リテラル塊に対する `std::string_view::find()` 最適化は維持する

### 5. `wildcard_find` / `wildcard_find_all` の共有最適化

`find` 系 API は現在、各開始位置から一般 matcher を再試行している。これを以下の方針で減らす。

- 単純 glob では greedy matcher を再利用する
- 固定プレフィックスを持つパターンでは、先頭候補を文字単位で総当たりせず、プレフィックス一致位置だけを候補にする
- 一般 matcher のメタデータを共有し、`match` と `find` 系でパターン解析ロジックを重複させない

## 互換性

- ワイルドカード構文の意味は変えない
- 不正または不完全な構文をリテラル扱いする既存挙動は維持する
- 文字集合、否定集合、alternatives、escape の既存テストはそのまま通す
- `wildcard_find` は **最初に見つかる開始位置** を優先し、その開始位置で複数の非空一致がありうる場合は **現行どおり最短の非空一致** を返す
- `wildcard_find_all` は **非空一致のみ** を返し、探索順序と非重複の挙動は現行実装を維持する

## テスト方針

- `test/test_wildcard.cpp` で既存挙動を維持する
- 必要に応じて以下の回帰テストを追加する
  - 単純 glob が greedy path に入っても既存結果が変わらないこと
  - `wildcard_find` / `wildcard_find_all` がプレフィックス最適化後も同じ結果を返すこと
  - 不完全な `[` / `(` を含むパターンの既存挙動が維持されること
- `bench_wildcard`
- `bench_pattern_comparison`
- 改善確認の主対象は `a*b` 系、文字集合、否定集合、alternatives、`*.[hc](pp|)`、および `find` 系に追加する回帰ケースとする

## 実装順

1. 前計算メタデータ構造を追加する
2. 単純 glob 判定と greedy matcher を追加する
3. 一般 matcher を前計算メタデータ参照型に置き換える
4. `wildcard_find` / `wildcard_find_all` に共有最適化を適用する
5. テストとベンチで挙動・改善を確認する

## リスクと対策

- **リスク:** 前計算メタデータが複雑化して constexpr 制約に引っかかる  
  **対策:** 固定長配列ベースで実装し、必要最小限の情報だけ持つ

- **リスク:** greedy path と一般 path で結果差異が出る  
  **対策:** greedy path は構文制約を厳密に限定し、それ以外は一般 path に送る

- **リスク:** `find` 系の候補スキップで最初の一致を落とす  
  **対策:** プレフィックスがある場合だけ候補を絞り、ない場合は従来互換の探索に寄せる
